# Глобальные инструкции

Я только начинаю работать с кодом — объясняй решения простыми словами, без лишнего жаргона.

## Оркестрация: кто что делает

Основной чат (Opus) — «дирижёр»: изучает задачу, планирует, принимает решения, проверяет результат. Рутинный код он не пишет сам, а после утверждения плана раздаёт сабагентам:

| Агент | Модель | Когда |
|---|---|---|
| `Explore` (встроенный) | — | поиск по большому коду, когда нужен только вывод |
| `implementer` | Sonnet | понятные шаги плана: обычный код, вёрстка, CRUD, правки по списку |
| `quick-helper` | Haiku | механика: запустить тесты/сборку и пересказать, переименовать, мелкая правка |
| `build-fixer` | Sonnet | упала сборка/тесты/типы с конкретными ошибками |

Сам основной чат делает: архитектуру, неясные баги, безопасность, всё, где нужно решение, а также проверку работы сабагентов.
Перед кодом с внешними библиотеками/фреймворками сверяйся с актуальной документацией через context7, а не по памяти.
Мелочь на 1–2 правки делай сам — запуск агента дороже самой правки. Независимые шаги отдавай агентам параллельно.

## Рекомендации в конце каждого плана

Когда готовишь план (перед ExitPlanMode), добавь в конец раздел **«Рекомендуемая настройка»**:

1. **Кто выполняет.** Какие шаги каким агентом пойдут (по таблице выше).
2. **Скиллы и плагины.** Что из установленного задействовать; что из «Выключено, но доступно» включить; если нужного нет — плагин из `claude-plugins-official`. Если и там нет подходящего, можешь поискать стороннее (GitHub, другие маркетплейсы) — но только когда задача от этого заметно выиграет, не в каждом плане. Пометь как **«стороннее»** и укажи: источник и популярность, что внутри (хуки, MCP, скрипты), сколько будет стоить контекста. Перед установкой проверь его файлы.
3. **MCP.** Какие пригодятся/стоит подключить. Если MCP не подключается или требует авторизации — так и скажи. Не держать в проекте больше ~10 MCP.
4. **Модель и effort основного чата.** Если текущие не подходят под задачу, подскажи команду (`/model`, `/effort`) — сам ты их не переключишь.
5. **Автоматизации проекта.** Если у кодового проекта нет своей папки `.claude/`, предложи скилл `claude-automation-recommender` (плагин claude-code-setup).

Правила:
- 0–3 пункта на категорию, только то, что реально нужно. Если ничего — «Дополнительная настройка не нужна».
- Ничего не устанавливай и не включай без моего явного разрешения.
- **После одобрения плана**, если в «Рекомендуемой настройке» есть что включить/установить/скопировать, сначала задай мне вопрос через AskUserQuestion с множественным выбором: каждый пункт — отдельный вариант (что это и зачем в одну строку, самые полезные помечены «(Recommended)»). Подключи только выбранное, затем одним коротким сообщением скажи, что нужно сделать мне (`/reload-plugins`, `/model`, `/mcp`), и переходи к работе. Если подключать нечего — вопрос не задавай.
- Не выдавай уже подключённое за «новое».

## Выключено, но доступно

Установлено, но не грузится в контекст. Предлагай, когда задача явно выиграет.

Плагины (включение: `claude plugin enable <плагин> --scope project` в папке проекта, или `--scope user` глобально; потом новый чат или `/reload-plugins`):
- `impeccable@impeccable` — качество фронтенд-дизайна: `/impeccable polish`, `audit`, `critique`, `animate` и др. Включённый, проверяет UI после правок (хуки).
- `figma@synced` — работа с Figma, дизайн ↔ код.
- `brightdata-plugin@synced` — скрейпинг, веб-исследования, данные с Amazon/LinkedIn/соцсетей.
- `desktop-commander@synced` — постоянные терминалы, REPL, долгие процессы.
- `playwright@claude-plugins-official` — браузер: открыть сайт, сделать скриншот, проверить вёрстку и формы. Для фронтенда (особенно вместе с impeccable).
- `typescript-lsp@claude-plugins-official` — точная навигация по JS/TS-коду в больших проектах. Нужно: `npm install -g typescript-language-server typescript`.
- `pyright-lsp@claude-plugins-official` — то же для Python. Нужно: `npm install -g pyright`.
- `security-guidance@claude-plugins-official` — ревью безопасности после правок (хуки, тратит токены). Только для проектов с логином, оплатой, личными данными.
- `commit-commands@claude-plugins-official` — `/commit`, `/commit-push-pr` для работы с git.

Библиотека скиллов `~/.claude/skill-library/` (подключение: скопировать папку скилла в `<проект>/.claude/skills/`):
- `design-taste-frontend` (Taste Skill) — «не шаблонный» дизайн лендингов, портфолио, редизайнов. Тяжёлый (~22k токенов при вызове) — не для дашбордов и обычных форм.
