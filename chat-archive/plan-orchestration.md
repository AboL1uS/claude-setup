# План: оркестрация моделей + дизайн-скиллы «выключено, но под рукой»

## Context
Хочется, чтобы Claude Code:
- сначала строил план (уже включено: `defaultMode: plan`), а в конце плана рекомендовал, что включить из уже установленного (уже есть в `~/.claude/CLAUDE.md`);
- не тратил сильную модель на рутинный код — делегировал его дешёвым сабагентам;
- имел под рукой дизайн-скиллы (Impeccable, Taste Skill, `/impeccable animate`), но не грузил их в каждый чат.

### Вердикт по Everything Claude Code (ECC) — целиком НЕ ставить
- Хук блокирует dev-серверы вне tmux → на Windows `npm run dev` будет падать.
- Агенты на `model: opus` с описанием «MUST BE USED for all code changes» → дорогое ревью на каждую правку (прямо против цели экономии).
- Правила навязывают TDD и 80% покрытия, SessionStart-хук добавляет текст в каждый чат.
- Многое уже встроено: агенты Plan/Explore, `/code-review`, `/security-review`, `/simplify`.
→ Берём только идеи (агент для ошибок сборки, правило «не включай >10 MCP»), переписанные под нас.

### Impeccable и Taste Skill — брать, но выключенными
- Impeccable — один скилл `impeccable` с 24 командами (`/impeccable animate`, `polish`, `audit`, `critique`…), ставится как плагин → можно выключить глобально и включать по проекту.
- Taste Skill — набор SKILL.md-файлов (13 вариантов), не плагин → берём только основной `design-taste-frontend` и храним в «библиотеке», которую Claude не сканирует.

## Шаги

### 1. Модель основного чата — `~/.claude/settings.json`
- `"model": "opus"`, `"effortLevel": "medium"` (сейчас `xhigh`). Остальное не трогать.

### 2. Три глобальных сабагента — `~/.claude/agents/` (новая папка)
Каждый файл с frontmatter `name`, `description`, `tools`, `model`, `effort`. Описания короткие и без «MUST BE USED», чтобы не срабатывали без нужды.
| Файл | Модель / effort | Для чего |
|---|---|---|
| `implementer.md` | sonnet / medium | Выполняет утверждённые шаги плана: обычный код, вёрстка, CRUD, правки по списку |
| `quick-helper.md` | haiku / low | Механика: запустить тесты/сборку и пересказать результат, переименования, мелкие правки, форматирование |
| `build-fixer.md` | sonnet / medium | Чинит ошибки сборки/тестов/типов минимальными правками (идея из ECC, переписана) |
Плюс уже встроенные: `Explore` (поиск по коду), `Plan` (архитектура).

### 3. Правила оркестрации — дописать в `~/.claude/CLAUDE.md`
Коротко (файл грузится в каждый чат):
- Основной чат (Opus) = «дирижёр»: исследует, планирует, принимает решения, проверяет результат.
- После утверждения плана рутинные шаги отдаёт `implementer`/`quick-helper`/`build-fixer`; сложное (архитектура, хитрые баги, безопасность) делает сам.
- В разделе «Рекомендуемая настройка» указывать, какие шаги каким агентом пойдут.
- Не держать включёнными >~10 MCP в проекте.

### 4. Impeccable — плагин, выключенный глобально
- `claude plugin marketplace add pbakaus/impeccable` → `claude plugin install impeccable@<marketplace>` (точное имя взять из вывода) → `claude plugin disable … --scope user`.
- Включение в дизайн-проекте: `claude plugin enable … --scope project`.

### 5. Taste Skill — в «библиотеку» `~/.claude/skill-library/`
- Скачать только `design-taste-frontend` в `~/.claude/skill-library/design-taste-frontend/` (папка вне `skills/` → не грузится).
- Подключение в проект: скопировать в `<проект>/.claude/skills/`.
- Прочитать SKILL.md перед сохранением (сторонний файл).

### 6. Каталог в `~/.claude/CLAUDE.md`
Расширить раздел «Выключенные плагины» → «Выключено, но доступно»: Impeccable (плагин), Taste Skill (библиотека) — с одной строкой «когда полезно» и командой включения, чтобы Claude мог их предлагать в планах.

## Проверка
- `claude plugin list` — impeccable установлен и `disabled`.
- `claude agents` — видны `implementer`, `quick-helper`, `build-fixer` с нужными моделями.
- Открыть новый чат → `/model` показывает Opus; в контексте нет описаний Impeccable/Taste.
- Тест: в новом чате попросить небольшую задачу → в плане должен быть раздел «Рекомендуемая настройка» с распределением шагов по агентам.
